# Gramin Vaani Saathi — AI-Powered Voice Financial Companion for Rural Communities

A voice-first financial assistant for people who may not read, may not have a
stable network, and are disproportionately targeted by financial fraud. Speak or
type in Hindi, English, Tamil or Telugu; every answer is shown *and* spoken.

> ### ⚠️ This is a simulation
> Every banking and UPI operation runs against a **sandbox ledger inside this
> project's own database**. No real bank, payment service provider, or payment
> network is contacted. The app never asks for and never stores a real account
> number, card number, Aadhaar number, or bank PIN, and it never asks for an OTP
> belonging to a real bank or payment app. Sign-up does use a one-time code, but
> it is **this project's own code**, generated and checked locally — and no SMS
> gateway or email provider is wired up, so the code is printed to the server log
> and shown on screen (see [Signing up](#signing-up)). Scheme eligibility is a
> **guide, not a decision**, and the financial-literacy content is **educational
> only** — not personalised investment or financial advice.

---

## What it does

| Feature | How |
|---|---|
| Voice-first interface | Browser speech or `faster-whisper` → **IntentNet** → dialog → spoken reply; a typed command bar on every screen runs the same path |
| Four languages | Hindi, English, Tamil, Telugu — including romanised Hindi ("paise bhejo") |
| UPI & banking help | Simulated balance, history and transfers; **no money moves without a yes the user has heard and seen** |
| Government schemes | 20 schemes as declarative rules with a reason per rule; multilingual semantic search ("मुझे खेती के लिए पैसा चाहिए" → PM-KISAN) |
| Financial literacy | 8 one-minute spoken lessons with server-graded quizzes and progress |
| Scam detection | **ScamNet** (MuRIL + rule features) with spoken reasons, and a report flow that leads with the 1930 helpline |
| QR & banknote checks | OpenCV QR decoding, UPI verification, sticker-tamper detection; note recognition |
| Offline mode | Cached shell and reads; confirmed transfers queue in IndexedDB and replay **exactly once** |
| Easy navigation | A sidebar naming every function with a one-line description; icon + word + audio on every control |

## Results

Every number is on **hand-written test data kept out of training**. Full
tables, ablations and every mistake: [`docs/RESULTS.md`](docs/RESULTS.md),
regenerated by `python ml/evaluate.py`.

| Component | Test set | Result |
|---|---|---|
| **IntentNet** (MuRIL, 14 intents) | 183 utterances, 4 languages | **85.8%** accuracy, 0.860 macro F1 (keyword baseline 71.0%) |
| Confidence gate | same | acts on 79.8%, wrong-and-acted 3.3% (was refusing 79.8% at the old threshold) |
| **ScamNet** (3 classes) | 83 messages, incl. unseen scam types | **90.4%** accuracy, 0 scams missed, 7.1% false alarms on genuine messages |
| Scheme search (e5 + keywords) | 48 queries naming no scheme | hit@1 **0.875**, hit@3 0.958 |
| QR sticker detection | 120 synthetic posters | AUC **0.92**, 0% false alarms, 55% of stickers caught |
| Voice pipeline (RTX 4070) | 7 clips | p50 **0.55 s**, p95 0.60 s against a 4 s budget; 6/7 intents right |
| **NoteNet** | — | not trained: needs photos of real notes (see Limitations) |

## Architecture

```
PWA (no-build ES modules · service worker · IndexedDB action queue)
        │  REST + JSON
Django 5 + DRF ──── Celery workers ──── Redis
        │                  │
   PostgreSQL        ai/ adapter layer ── local: models in-process
                                       └─ remote: ai/server.py model server over HTTP
```

Views never import a model. They call the interfaces in
[`backend/ai/base.py`](backend/ai/base.py) through
[`ai/registry.py`](backend/ai/registry.py). With `AI_BACKEND=remote` the same
calls go to [`backend/ai/server.py`](backend/ai/server.py), so GPU memory is paid
once per model server instead of once per web worker, and web replicas stay
small and CPU-only. If the model server is unreachable, intent falls back to a
keyword baseline and scam checks to the rule layer — degraded, never broken.

Models load once per process at start-up ([`ai/warmup.py`](backend/ai/warmup.py)),
because the first user should not pay the ~12 s it takes.

## Setup

Python 3.11. A CUDA GPU is optional — CPU works, more slowly.

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Linux/macOS: .venv/bin/pip
.venv/Scripts/pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cu121
cp .env.example .env
python backend/manage.py migrate
python backend/manage.py seed_demo
python backend/manage.py runserver
```

Open <http://localhost:8000/>. Django serves the app and the API from one
origin. API docs: <http://localhost:8000/api/docs/> (also committed as
[`docs/openapi.yml`](docs/openapi.yml)).

The trained models are not in git (`ml/artifacts/` is ~2 GB). Train them —
`python ml/train_intent.py --train-embeddings` and `python ml/data/generate_scam_data.py && python ml/train_scam.py`,
about 8 minutes together on an RTX 4070 — or unpack the release archive into
`ml/artifacts/`. Without them the app still runs, on the fallbacks above.

`seed_demo` creates **sita**, **ramesh**, **lakshmi** and the shop **ramkirana**,
all with password `demo1234` and play money. The sign-in screen offers the first
three as one-tap buttons.

### Tests

```bash
cd backend && ../.venv/Scripts/python -m pytest
```

27 tests, weighted towards the money path: the same idempotency key moves money
once, offline replay settles once, a transfer never executes on the first
utterance, an unclear answer re-asks instead of paying, and the remote adapters
fall back when the model server is down — plus catalogue validation and the API
contracts the frontend depends on.

### Signing up

"Create a new account" runs three steps: a mobile number or email address, the
six-digit code, then a name and password. The account opens with ₹2,000 of play
money.

**There is no SMS gateway and no email provider in this project.** The code is
written to the server console, and in development the app also shows it on the
code screen behind a "no SMS was sent" label (`OTP_ECHO_IN_RESPONSE = False` in
`prod.py` turns that off). Everything around the delivery hop is real — see
`backend/apps/accounts/otp.py`:

| Property | Where |
|---|---|
| Codes generated with `secrets`, never `random` | `otp.issue` |
| Stored as a password hash, never plaintext | `OtpChallenge.code_hash` |
| Expire (5 min), single-use, lock after 5 wrong tries | `otp.verify` |
| Resend cooldown (30 s) + hourly cap per destination | `otp._enforce_send_limits` |
| Phone/email read from a **signed token**, not the request body | `RegisterView` |
| No server-side half-signed-up session | `otp.make_verification_token` |

### Docker

```bash
docker compose up --build                                            # CPU
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build   # GPU model server
```

Five services — `web`, `worker`, `models`, `db` (Postgres), `redis` — the same
split as the diagram, with web and worker calling the model server over HTTP.
Mount trained models at `ml/artifacts/`.

> **Verification status:** the development machine has no Docker, so the stack
> has not been run end to end. What *was* checked with the production settings
> it uses: `manage.py check`, migrations and seeding against a fresh database,
> `collectstatic`, the Celery app loading with the compose command line, the
> PWA and API being served with the compose `ALLOWED_HOSTS`, and the model
> server and remote clients working over HTTP.

## Frontend

`frontend/` is plain HTML, CSS and ES modules — **no build step**; Django serves
the files directly.

- **Layout.** A sidebar lists every function with a one-line description (the
  person this is for may not know what "schemes" means; "find schemes you
  qualify for" tells them). The top bar is always a voice and typing command
  line, and its answer appears on every screen. The overview shows balance,
  quick send, a fraud check, recent activity, schemes, lesson progress and
  scanning together. From 1366×768 up, every view fits the screen — lists
  scroll inside their own card, never the page. On a phone the sidebar becomes a
  drawer and views stack.
- **Money.** A transfer — tapped or spoken — always ends in a confirmation
  dialog that is also read aloud. Its idempotency key is minted *before* the
  network is involved, so the same action keeps its identity whether it is sent
  now or replayed from the offline queue tomorrow.
- **Languages.** Every string exists in all four languages (`i18n.js`); server
  replies, scheme reasons and lessons come back in the selected language. Names
  are shown in the script of the UI language, never Devanagari inside a Tamil
  sentence.
- **Honesty details.** A cached balance is always stamped with the time it was
  read. A QR code's own payee name is reported as a *claim* unless the address is
  verified — a fraudster's sticker carries the shop's real name.

## Limitations

- **NoteNet is not trained.** It needs 60–100 photographs of each real banknote,
  taken by hand, plus a test set photographed in a separate session.
  `ml/train_notes.py` is ready; until then the note endpoint uses a colour
  heuristic, says so, and caps its confidence at 60%.
- **Telugu speech recognition is weak** with Whisper `small`: in the benchmark it
  transcribed Telugu into Devanagari. Typing is the fallback; `ASR_MODEL_SIZE=medium`
  is the next step.
- **ScamNet is sensitive to phrasing on scam types it never trained on.** It
  catches the "Mum, this is my new number" scam as written in the test set, but
  scores a shortened version of the same message as safe. The fix is more varied
  training data.
- **The 0.7 scam blend weight adds no accuracy** on the test set (the fine-tuned
  model is near-certain); the rules contribute the explanations.
- **Synthetic data.** The scam corpus and the QR tamper posters are generated.
  The test sets are hand-written, but field numbers need real messages, real
  shop counters and real users.
- **Eligibility rules are simplified**, for teaching. The app says "you appear
  to qualify", never "you qualify".
